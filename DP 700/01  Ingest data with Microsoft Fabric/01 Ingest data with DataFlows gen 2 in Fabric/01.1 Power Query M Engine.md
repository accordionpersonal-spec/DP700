# Power Query M Engine — What It Actually Is
*DP-700 · supplement to "01 Introduction" (Core Concepts)*

## ⚡ The simple version (30 seconds)
- **M is a language. The engine is the thing that runs it.**
- You click buttons in Power Query — remove a column, filter rows,
  change a data type. Behind each click, Power Query **writes a line
  of M code for you**. You never have to type it.
- The **M engine** then reads that code and does the actual work of
  fetching and reshaping the data.

> Think of it like **recording a macro**: you do it once with the
> mouse, it saves the steps, and it replays them identically on every
> refresh. That's the "repeatable ETL" wording in the Introduction.

---

## Careful with the wording
The Introduction says the M engine *"provides visual data wrangling."*
Strictly, it doesn't:

| Piece | What it does |
|---|---|
| Power Query **editor** (the UI) | Gives you the visual, click-based wrangling |
| **M** | The language those clicks get written into |
| **M engine** (mashup engine) | Executes the M code |

So the honest chain is:

```
You click in the UI  →  UI writes M code  →  M engine executes it
```

Minor distinction, but exam questions lean on it.

## What the code looks like (you don't write this)
Home → **Advanced Editor** in any Dataflow Gen2 shows the steps
your clicks produced:

```m
let
    Source = Sql.Database("myserver.database.windows.net", "SalesDB"),
    Orders = Source{[Schema="dbo", Item="Orders"]}[Data],
    #"Filtered Rows" = Table.SelectRows(Orders, each [OrderDate] >= #date(2024, 1, 1)),
    #"Removed Columns" = Table.RemoveColumns(#"Filtered Rows", {"InternalNotes"})
in
    #"Removed Columns"
```

Just named steps, each one feeding the next. This M script **is** the
dataflow's saved definition — that's why every refresh behaves the same.

**One gotcha worth remembering: M is case-sensitive.**
`Table.SelectRows` works; `table.selectrows` errors out.

---

## Why it matters later
- **Query folding** — the engine tries to translate your steps into the
  source's own query (e.g. real SQL) and let the source do the work.
  See *Gotchas → Query Folding Limits* in the Introduction.
- **It's single-node**, not a Spark cluster. No scale-out across
  executors. That's the actual reason big transformations belong in
  **Notebooks (PySpark)** instead of Dataflows Gen2.

---

## Where else you'll meet it
Same engine powers **Power BI Desktop**, **Excel** (Get & Transform),
**Dataflows Gen1**, and **Analysis Services** — so M knowledge carries
across all of them.
