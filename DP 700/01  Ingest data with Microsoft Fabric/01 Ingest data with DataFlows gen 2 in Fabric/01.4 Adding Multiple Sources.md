# Adding a 2nd Source to a Dataflow — Click Path
*DP-700 · supplement to "03 Explore Dataflows Gen2" (Queries & Staging Logic)*

## ⚡ The simple version (30 seconds)
One dataflow can hold **many sources**. Each source becomes its own
**query** in the left pane, and they're **independent** — adding a
second one doesn't touch the first or its steps.

---

## Adding the 2nd source
1. Look at the **Queries** pane on the left — your first source is
   sitting there as one query.
2. **Home** ribbon → **Get data** → pick your connector
   (→ **More...** for the full list).
3. Sign in / enter connection details → pick the table or file → **Create**.
4. A **new query appears** in the left pane. Your first query and all
   its transformations are untouched.
5. Transform this second one however you need.

Repeat for a 3rd, 4th, etc.

---

## Combining them (only if you want one output)
**Home** → **Combine** →

| Option | What it does | Needs |
|---|---|---|
| **Merge queries** | Join — adds *columns* from the other query | A matching key column |
| **Append queries** | Union — stacks *rows* underneath | Same/similar column names |

Pick **"Merge queries as new"** / **"Append queries as new"** — that
creates a **third** query and leaves both originals intact. Far easier
to debug than modifying one in place.

---

## Destinations are per-query
- You **don't have to combine** at all. Two sources can just load into
  two separate tables.
- **Data destination** is set per query, in the **Query Settings pane**
  (bottom-right when a query is selected).
- If you merge into a third query, set the destination on **that one
  only** — otherwise you also land the intermediate queries.
- Or use **Disable Load** on the intermediates (see file 03, line 28).

---

## The folding catch
A merge across **two different source types** (Azure SQL + a CSV, say)
**can't fold** — no single source can execute it. That's exactly the
case where staging earns its keep.
